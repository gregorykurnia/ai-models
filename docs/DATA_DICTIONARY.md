# Leaderboard data dictionary

The schema is declared in `src/lib/contract.ts`. All nullable source values remain null when absent. Document IDs are deterministic SHA-256 based identifiers; evaluation IDs use sheet slugs.

| Collection | Identity and fields | Meaning |
| --- | --- | --- |
| sourceAssets | content hash, filename, captured_at, imported_at, source_kind | Provenance for workbook imports and supplementary Artificial Analysis result captures. SHA-256 covers the captured source data. |
| evaluations | slug, display_name, source_title, source_url, category, metric_key, metric_label, score_kind, score_unit, score_min/max, captured_at, source_asset_id, notes | One distinct evaluation. `published_snapshot_id` points to its visible immutable snapshot. Row and coverage counts are copied from that validated snapshot for catalog reads. Optional `metric_group`, `metric_indicator`, `metric_color`, and `source_tab` identify separately ranked metrics that share a source results tab. |
| providers | provider-label hash, slug, display_name, aliases | Exact source provider labels. No implicit normalization. |
| models | provider and model-label hash, provider_id, canonical_name, display_name, release_date_label, aliases, created_at | Provider plus exact model variant. Canonical name initially equals the source model label. |
| snapshots | evaluation and workbook hash, captured_at, status, row_count, cost_label_count, precise_cost_count | One capture per evaluation. Cost counts refer to evaluation-specific workbook cost fields. Importing and validated snapshots stay hidden until published. |
| snapshots/{id}/entries | snapshot and source-row hash, evaluation_id, model_id, provider_id, source_rank, score_value/display, confidence interval, release label, cost_usd/display/status, source_sheet/row/asset | Immutable source result. Source row is the one-based Excel row. Provider and model labels are denormalized for display. |
| data/intelligence-index-costs.json | source URL, capture time, model slug/name/provider, cost_usd | Dated capture of the Intelligence Index page's `intelligenceIndexCostPerTask` values; linked from cost cells in the master and individual evaluation tables. |
| data/aa-model-speed.json | format_version 2, source URL, capture time, sources, model AA ID/slug/name/provider/URL, time_per_task_s, first_answer_s, evaluation_times_s, provenance | Overall task time is seconds from `intelligenceIndexTimePerTask`; first answer is creator-API `performance.headline.timeToFirstAnswerToken` (flattened to `headline` in manifests). Per-evaluation times are exact seconds from `data/aa-speed-captures.json`: what each page's Time per Task chart plots, or the page payload's `evalTimePerTask` on pages without that chart; the legacy inline `intelligenceIndexEvaluations[].timePerTask` path remains supported. Each non-null metric's `provenance` references a `sources` entry with its actual retrieval timestamp, URL and SHA-256 evidence. Retains any model with at least one value. Missing values remain absent/null, never estimated. Master task time formats as minutes (one decimal), first answer as seconds (one decimal); both sort fastest first, missing last. CSV exports precise minutes and seconds after cost. Speed does not affect Aggregate Score or Firestore snapshots. |
| data/aa-speed-captures.json | format_version 1, unit_evidence, evaluations with evaluation_slug, source_url, captured_at, title, unit, metric_path, time_chart_present, selected_model_count, selector, items (id, name, url, seconds) | Timing-only capture of nine official evaluation pages, including CritPt v2's **hard** subset and Terminal-Bench-Science. Selects all models and checks the context length against the selector; missing times are not rows. Seven pages store what their Time per Task chart plots (`metric_path` `TimePerTaskChart.items[].timePerTaskSeconds`, the items the bar chart is built from); the chart must hold every model the page times, or the capture fails. AutomationBench-AA and AA-Omniscience have no time chart and keep `EvaluationDataProvider.selectedModels[].evalTimePerTask`. Which pages have the chart is fixed in `evaluationTimingSources` (`timeChart`), so a chart appearing or vanishing fails the capture. AA recomputes these times as its measured output speeds change, so a capture goes stale within hours: run `capture:aa-speed` and `import:aa-index-costs` together, then `scripts/check-aa-time-charts.mjs`, which compares every bar with the stored time to AA's one decimal (minutes; `<0.1` labels count as below 0.1). The official loader defines seconds as output tokens per task divided by output speed, plus tool milliseconds per task divided by 1,000 where supplied. Unit evidence saves the loader URL/hash and defining excerpt. IDs identify effort variants because AA now links several variants to the same family URL. |
| ingestionRuns | run ID, source_asset_id, started_at, completed_at, status, accepted_rows, error | Trusted publishing run and failure reason. |
| ingestionIssues | run_id, sheet, message, severity | Reviewable source anomalies and normalization backlog. |

## Numeric semantics

## Master comparison policy v1 (beta)

`src/lib/master.ts` groups entries by provider, model, and reasoning/fallback variant. It accounts for known differences in how evaluation sheets format the same variant (for example, “Adaptive Reasoning, Max Effort, Default Fallback” and “max with fallback”). Effort and fallback variants remain distinct. Each evaluation cell links the model's rank to its entry on that leaderboard. The Cost per Intelligence Index task column links to the matched Artificial Analysis model profile. Aggregate Score averages the available ranks from nine designated evaluations.

Duplicate selection uses ascending source rank, source row, then entry ID and emits an issue. Full source entries remain server-side for provenance. “Not ranked” appears only when there is no entry for the matched model and variant in that evaluation. Index sorting uses source rank ascending by default, with missing entries last in both directions. Ties use the best rank across evaluations other than SWE-Atlas-QnA, followed by the exact model name, provider, and model ID. Local JSON and Firestore share the same aggregation.

Home URL keys `mq`, `mp`, `ms`, `md`, `mi`, and `mz` store search, provider, sort, direction, page, and size. The section anchor is `master-leaderboard`. Beta promotion requires product feedback; runtime performance and Firestore reads should be measured in the deployed environment.

- `score_value` stores the Artificial Analysis value as captured, without cross-evaluation normalization. `score_display` formats it to six significant figures.
- `score_kind` distinguishes Elo, percentage, integer scores, and the signed index. Signed index limits are -100 to 100. Percentage limits are 0 to 100.
- Entry `cost_usd` and `cost_display` hold the cost per task shown on that evaluation's Artificial Analysis page. Costs are read from each page's “vs. Cost per Task” chart, because the “Cost per Task” bar charts no longer expose their values. The AA-Briefcase cost series reports the whole run, so it is divided by the 91 tasks. They are not the values shown in leaderboard cost columns. Those columns use the separate `data/intelligence-index-costs.json` snapshot: the weighted-average USD cost per Artificial Analysis Intelligence Index task. See the [Artificial Analysis methodology](https://artificialanalysis.ai/methodology/) and [Intelligence Index cost definition](https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index). The displayed value links to its model profile and sorts by the captured precise USD value; a missing profile value displays as a dash. No costs are estimated.
- `cost_status` is `exact` or `missing` for the evaluation-specific cost. Exact cost can exist with no label; this status does not control the separate Intelligence Index task cost column.
- Confidence interval deltas are parsed only from supplied Elo interval labels. Source interval text remains intact. Interval sorting uses the upper delta.
- Release dates retain source month/year labels. Sorting uses the parsed date and places missing/unparseable dates last.

## Ordering and ingestion

Ranks are assigned by descending score. Exact score ties share a rank and keep source row order. Alternate rank sorts use source rank then model label and source row as deterministic tie breakers. Cost sorts use the separate Intelligence Index profile value and keep missing values last in both directions.

`scripts/capture-aa-evaluations.mjs` saves the chart and table data behind Artificial Analysis evaluation results to `data/aa-captures/`. `scripts/import-aa-evaluations.ts` rebuilds the evaluations from those captures. Missing creators, unknown chart titles, and duplicate models within an evaluation reject the import. The Sep 29 workbook remains in the published history only.

The 25 Nov 2026 refresh supplies 20 leaderboards, including Terminal-Bench 4.1, AA-Omniscience Business, legacy CritPt, both CritPt v2 subsets, and SWE-Atlas-QnA. The CritPt boards have separate source links, scores, ranks, and costs. The Hard Subset uses its captured evaluation timing. The Full Set and legacy CritPt display Intelligence Index task time.

Terminal-Bench 4.1 supplies one of the nine Aggregate Score dimensions. Its raw scores are fractions displayed as percentages to two decimals. Scores and per-task cost come from the 4.1 score and score-vs-cost charts. Time per task uses the `terminalbench-4-1` timing source.

SWE-Atlas-QnA comes from the [Artificial Analysis Coding Agent Index](https://artificialanalysis.ai/agents/coding-agents). The [capture inventory](SWE_ATLAS_QNA_CAPTURE.md) maps 41 setups to master models, one per model and effort (25 Nov 2026). AA also runs GPT-6 Luna and GLM-5.3-Flash in other agents; the importer skips those setups. The importer converts pass-rate fractions to percentages and assigns competition ranks among the mapped rows. SWE-Atlas QnA follows FrontierCode 2.0 in the master table. The nine dimensions used by Aggregate Score exclude this column. The evaluation has no separate cost or timing data.

On an AA refresh, check the `swe-atlas-qna-aa` messages from `npm run import:aa-evaluations`. When the importer prints an unmapped setup, update the capture inventory and the `expectedRows` list in `scripts/import-aa-evaluations.ts` for any new setup with a matching master row. Missing expected setups, mappings without a master row, and two mapped setups with the same model and effort stop the import.

For speed refreshes, run `PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs npm run capture:aa-speed`, then `npm run import:aa-index-costs`, then **`npm run import:aa-evaluations` last** (it restores the evaluation capture's canonical cost names). The model-family manifest no longer includes per-evaluation timings. Its importer therefore requires all nine evaluation timing payloads retrieved on the same UTC date as the current model payload, rejects incomplete selectors, empty payloads, invalid values, duplicate or unknown model IDs, and stages both outputs before replacing them. `sources.model-payload` records the resolved family-page URL, page hash and public model-manifest URL/hash. Each `sources["evaluation:<slug>"]` records its capture hash (`SHA-256(JSON.stringify(evaluation))`), unit evidence and a pointer into the committed evidence file. Record provenance keys mirror the timing fields; null metrics have null provenance. Evaluation evidence keeps its own capture timestamp even though a record's `captured_at` is the model payload retrieval time.

AutomationBench-AA and AA-Omniscience no longer display Time per Task charts on 2026-11-16, but their public contexts still supply current timing values. Capture those fields directly; do not interpret a missing chart as missing data. The other seven pages are read from their Time per Task charts (same `evalTimePerTask` formula, read at the moment the chart shows it). A model AA has no creator-API speed for (no `headline`, no output speed) has no first answer and no evaluation times; on 2026-11-25 this dropped 12 older models (Gemma 4 E4B (Reasoning) among them), and none is on a live time chart. The nine timing sources include Terminal-Bench 4.1 and the CritPt v2 Hard Subset. See [the 16 Nov speed-source evidence](AA_SPEED_REFRESH_2026-11-16.md).

The timing capture and importer share `data/.aa-speed.lock` and refuse overlapping writers. Errors release the lock. An interrupted process can leave its PID in the lock: verify that process has stopped before removing the lock and retrying. A failed batch preserves the previous timing capture; a failed request, validation or staging write preserves both prior imports. The score and Briefcase captures are independent and need no repeat for a timing-only refresh.

To refresh PersonalityBench, run `PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs npm run capture:aa-personalitybench`, then `npm run import:aa-personalitybench`. The capture requires AA's complete model selection and one judged record per selected model. The import writes the bundled `data/aa-personalitybench.json` and its [capture inventory](AA_PERSONALITYBENCH_CAPTURE.md). It keeps AA's unrounded values and uses `null` for missing measures. Review changes to the model matches and missing values in the inventory, then commit the capture, import and inventory together. The bundled data reaches production with the site deploy.

Both commands share `data/.aa-personalitybench.lock`. After an interrupted run, check that the PID recorded in the lock has exited before removing it and retrying. An unexpected index or trait, a duplicate identity, or an invalid score stops the import before the output is replaced.

Local data is replaced only after validation succeeds. Firestore publication is atomic across evaluation pointers after staging; published snapshots remain immutable. Re-importing the same file preserves deterministic row IDs.

Intelligence Index v5.0.2 rows come from the Intelligence Index page captured 25 Nov 2026, with all 155 listed models. Its re-scored values and task costs replace v5.0.1. AA no longer lists Granite 4.2 3B, 8B or 30B in the Index or FrontierCode-AA 2.0; they keep their other evaluations. `scoring_status` follows Artificial Analysis's estimated flag: “Independently scored” or “Estimated”. Where the source flags a model as estimated and an earlier capture said the independent evaluation is still forthcoming, that wording is kept. Models with no flag keep their earlier status, or none. The cost column reads the 140 records in `data/intelligence-index-costs.json`.

The AA-Briefcase component indexes come from `data/aa-briefcase-components.json` and `data/aa-briefcase-rubric-refresh.json`, captured 25 Nov 2026. They add 291 rows each for Rubric Score (%), Analytical Quality Elo, and Presentation Elo, one per listed model. Rubric fractions are converted to percentages. The two Elo evaluations share the source tab “Analytical Quality & Presentation Elo” and retain separate graph indicator metadata. Component Elo confidence bounds are included when the source capture supplies them; unavailable bounds remain null. Costs are absent from this source capture. Firestore mode uses a published snapshot when available and falls back to this bundled capture until then.
