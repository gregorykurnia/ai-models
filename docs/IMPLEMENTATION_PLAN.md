# Terminal-Bench 4.1 replaces 4.0, and Intelligence Index v5.0.2

Swaps the Terminal-Bench 4.0 leaderboard for Terminal-Bench 4.1 everywhere it shows (its own page, the master column,
the average rank, speed and cost), and refreshes every AA page so the Intelligence Index and FrontierCode show AA's
new v5.0.2 scores. Earlier plans: [IMPLEMENTATION_PLAN-done.md](IMPLEMENTATION_PLAN-done.md) (Gemini 4 Neon and
Omniscience Business, live since 2026-11-19).

Working branch: `terminal-bench-4-1`, from `main` (`1f84972`). Every task commits and pushes there. `main` deploys to
production and moves only on O1. (The 12 unreleased docs and workflow commits on `neon-omniscience-business` stay
there; this release doesn't carry them.)

## What the owner asked (2026-11-24)

"Make quick plan to implement theres new changes in intelligence index and terminal bench 4.1 (replacing terminal
bench 4.0) for autorun."

Simplest design that meets it:

1. **Swap the evaluation:** a new `terminal-bench-4-1` evaluation takes 4.0's place in the capture, importer, master
   column, average rank and speed columns. 4.0 stops being captured or bundled. No new page type, no scoring change.
2. **Refresh:** the same full AA refresh as the Neon plan's 1.2, which brings in the v5.0.2 Index and FrontierCode.
3. **Saved tasks keep working:** one alias so `refresh:saved-tasks` moves a 4.0 weight onto 4.1. Risk it covers:
   once 4.0 is retired, every shared task that weights it is "blocked" until someone edits it by hand.
4. **Old links keep working:** `/leaderboards/terminal-bench-4-0` redirects to `-4-1`. Risk it covers: shared links
   and the `llms.txt` pages that AI assistants read would 404.

- **The 4.0 page is still live** (283 models) but is no longer in the Index.

## Decisions (defaults, so no task stops to ask)

- **Names:** id and slug `terminal-bench-4-1`, display name "Terminal-Bench 4.1", capture key `terminalbench-4-1`.
  The master label and column position are 4.0's. It stays in `aggregateDimensionIds` where 4.0 was. Scores show as
  percentages with two decimals, like 4.0.
- **4.0 is removed, not kept beside it.** Delete `data/aa-captures/terminalbench-4-0.json` and every 4.0 config
  line. The evaluation count stays at 20.
- **Its notes start fresh.** 4.0's note about GPT-6.1 Sol rows taken from model profiles doesn't carry over: 4.1
  imports only what its chart shows.
- **Historical docs stay as written.** The coverage reports and rank docs under `docs/` that name 4.0 were true on
  their dates. `docs/WORKFLOWS.md`'s evaluation table and `docs/DATA_DICTIONARY.md` are current docs and do change.
- **The playbook moves onto the new capture as a whole (owner, 2026-11-24: "we can also redo the terminal bench rank
  columns").** The full refresh moves every rank column, not only Terminal Bench, and the file states one capture date
  for its tables. So 1.5 redoes every rank from the new capture. It changes no pick; picks the new numbers would move
  are listed for the owner (O2).
- **PersonalityBench isn't recaptured.** AA didn't change it.
- **Retiring 4.0 in Firestore is the owner's step (O1).** `publish:data` never retires an evaluation.
